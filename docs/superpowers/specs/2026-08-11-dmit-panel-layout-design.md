# DMIT Surge 面板布局优化设计

## 目标

在不改变数据源、校准算法、告警阈值和异常处理的前提下，让用户更快看清每台服务器的使用率、已用量、剩余量和重置时间。

## 约束

- Surge Panel 内容为纯文本，不依赖富文本、文字颜色或等宽字体。
- 不使用空格模拟左右对齐。
- 继续通过卡片 `style` 和行首状态圆点表达整体及单机风险。
- 两台服务器仍各占三行，中间保留一个空行。
- 不改服务端 `summary.json` 结构。

## 已选方案

采用 A：使用率优先。

```text
DMIT 流量 · 22:31

🟢 3300GB · 已用 49.5%
1.63 TB / 3.30 TB · 剩 1.67 TB
12 天后重置 · ↓838.5 GB ↑795.3 GB

🟢 7000GB · 已用 8.5%
596.0 GB / 7.00 TB · 剩 6.40 TB
10 天后重置 · ↓302.3 GB ↑293.6 GB
```

## 信息层级

1. 首行：服务器简称与使用率，回答“当前风险高不高”。
2. 第二行：已用、套餐总量和剩余量，回答“具体还剩多少”。
3. 第三行：距离重置时间和 RX/TX 明细，作为次级诊断信息。

IPv4 不再常驻显示。IP 是稳定的识别信息，不参与日常流量决策；服务器以 `3300GB`、`7000GB` 区分已经足够。

## 状态规则

- 使用率低于 60%：🟢，卡片 `good`。
- 60%–79.9%：🔵，卡片 `info`。
- 80%–94.9%：🟠，卡片 `alert`。
- 95% 及以上：🔴，卡片 `error`。
- 数据超过十分钟未刷新：服务器首行追加 `⚠️ 数据已过期`，卡片为 `error`。
- 距重置三天以内：第三行保留现有时间告警符号。
- 单台失败：展示另一台并在末尾追加失败名称；全部失败：保持当前错误卡片。

## 修改范围

- 调整 `renderServer()` 的三行文本顺序与措辞。
- 标题改为 `DMIT 流量 · HH:mm`。
- 使用现有 `remainingBytes`，不新增数据计算。
- 保持请求、超时、校准、样式阈值和失败处理逻辑不变。

## 验收标准

- 正常状态输出与设计示例结构一致。
- 标题不包含用于伪对齐的连续空格。
- 每台服务器明确显示使用率、已用/总量、剩余量、重置天数、RX 和 TX。
- 过期、单台失败、全部失败以及四档使用率样式均通过自动化测试。
- 正式 iCloud 脚本与仓库版本一致，并通过 JavaScript 语法检查和渲染模拟。
